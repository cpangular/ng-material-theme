Angular Material

Angular Material reads its colours from --mat-sys-* tokens. One stylesheet maps them to this library's tokens, so a Material app is themed by the same few input variables, re-themed inside a nested region, and switched at runtime, with no Angular service in between.

The demo is a small Angular app built with Angular Material 21. Its theme select and mode buttons are Material controls driving the switcher from chapter 12. The dashed section at the bottom is a nested theme region: pick its theme and open its menu or dialog. The demo and this site share the stored theme, so changing one changes the other.

Two stylesheets, in order

npm install @cpangular/ng-material-theme @angular/material

The adapter is a second CSS file, material-adapter.css, loaded after core.css. In an Angular app both go in the styles list of angular.json, before your own stylesheet: 

"styles": [
  "node_modules/@cpangular/ng-material-theme/css/dist/core.css",
  "node_modules/@cpangular/ng-material-theme/css/dist/material-adapter.css",
  "src/styles.scss"
]

It sets every --mat-sys- colour token: primary is var(--color--primary), the surface roles are chapter 5's, and the roles only Material has (the -container colours, the -fixed family, inverse-surface, surface-tint, scrim, shadow) are computed from the same inputs with chapter 5's tone formula. The text roles on-primary, on-secondary, on-tertiary and on-error are the --contrast--high partners from chapter 3, so they keep their 4.5:1 guarantee for whatever colour you chose, which Material's fixed tones cannot promise (at the default tuning; chapter 10's high contrast blend can lower it). The six elevation levels --mat-sys-level0 to 5 are the --elevation-N shadows.

Nothing in the adapter is written by hand. At build time it calls the functions in @angular/material that define Material's light and dark role tables, feeding them palettes whose tones are tone(var(--theme--light--color--primary), 90) and so on, then joins each pair with light-dark(). A Material upgrade is a rebuild of this library, not a review of a mapping.

mat.theme() for everything but colour

Material's own mat.theme() mixin stays, without a color key. It still emits the typography tokens, the density tokens when the scale is below zero, and the shape and state-layer tokens it always emits. It does not emit elevation without colour, which is why the adapter does. Put it in your stylesheet on html: 

@use "@angular/material" as mat;

html {
  @include mat.theme((typography: Roboto, density: 0));
}

Do not pass color: it would emit --mat-sys- colour tokens on html that override the adapter's, and only on html, so nested regions would lose them. For the same reason do not include Material's mat.app-background() mixin: it writes an html rule that unsets --mat-sys-on-surface, and a plain html selector beats the adapter's zero-specificity rule on the root. Set the page colours yourself instead, as the demo does: body { background: var(--mat-sys-surface); color: var(--mat-sys-on-surface) }.

Two densities

Material density and chapter 11's --theme--density-scale are separate controls. Material's density key shrinks Material components by rewriting their own size tokens, in steps below 0; each component clamps at its own minimum, −3 for buttons and −5 for form fields. --theme--density-scale multiplies the --theme--size--N scale your own CSS uses. Set both when the whole page should tighten; a Material control does not read the library scale, and the library scale does not reach into a Material control.

Nested regions

The adapter is emitted under :where(:root, [theme]), the same selector core.css uses, so an element with a theme attribute (chapter 6) re-maps every --mat-sys- token for its subtree, and Material components inside it draw in that theme. The demo's region is one <section [attr.theme]="nestedTheme()">.

Overlays are the exception. A menu, dialog, select panel, tooltip or snackbar renders in the CDK overlay container at the end of <body>, outside the region that opened it, so it takes the page theme from <html>. For the page's own overlays that is right. For a region's overlays, put the region's theme on the panel when it opens. A menu panel has the menu's panelId: 

<button matButton [matMenuTriggerFor]="menu"
        (menuOpened)="themeMenu(menu, nestedTheme())">Menu</button>

themeMenu(menu: MatMenu, theme: string) {
  document.getElementById(menu.panelId)?.setAttribute("theme", theme);
}

A dialog's container is the surface, so the attribute goes there, reached from the component the dialog created: 

const ref = this.dialog.open(DemoDialog, { data: { theme } });
const host: HTMLElement = ref.componentRef!.location.nativeElement;
host.closest("mat-dialog-container")?.setAttribute("theme", theme);

The switcher in Angular

Import themeSwitcher from the package as in chapter 12. It touches <html> and localStorage as soon as it is used, so use it from afterNextRender, which runs once, in the browser, after the first render, and never on the server. Subscribe there and copy what it reports into signals; the template binds to the signals. 

constructor() {
  afterNextRender(() => {
    themeSwitcher.onChange((themes, current) => {
      this.themes.set(themes);
      this.theme.set(current);
    });
    this.themes.set(themeSwitcher.getThemes());
    this.theme.set(themeSwitcher.getCurrentTheme());
  });
}

The three-line head script from chapter 12 goes in index.html as before, so the stored theme is on <html> before Angular boots. Themes themselves are plain CSS rules in your stylesheet; the demo's three sit in styles.scss under mat.theme().
