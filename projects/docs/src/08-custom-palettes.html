Custom palettes

A palette beyond the six, with the whole variant family of chapter 4. This needs Sass.

The labels on the solid swatches use --contrast--high, as in chapter 3. Three kinds are left as they are on purpose: the tint digits use the page's text colour (tints have no contrast colour), the disabled swatch uses -disabled--contrast, and the emphasis row shows all three strengths. Some of these read below chapter 4's 4.5:1, which is expected.

Adding a palette

Name a palette in createTheme()'s colors map (chapter 7) that is not one of the six standard ones, and it becomes a palette. brand above takes the same two shapes as any palette: a single colour, or a light and dark pair. From then on every token the grammar in chapter 4 allows exists for it: --color--brand, --color--brand-darker-1--contrast--high, --color--brand-tint-3, and so on, with the same contrast guarantees.

Why Sass only

core.css works out the six standard palettes and nothing else; it cannot know your palette names. createTheme() writes the rules for any other name you give it into the theme's own rule, and plain CSS has no way to do that, so a seventh palette needs Sass. To recolour brand later, name it in another createTheme() call.

Where it lives

A custom palette belongs to the theme that declares it. Declare it in the default theme ($is-default: true, as here; this one is also selectable as theme="shop") to have it everywhere, or in a named theme to have it only inside that theme. Like error in chapter 6, it is not derived from primary, so a nested theme that does not declare it keeps its parent's brand. Two themes may declare the same palette name with different colours.
