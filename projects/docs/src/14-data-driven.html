Data-driven themes

A theme is a few input variables, so it can come from anywhere: a JSON file, a database row, a form. One call turns such a row into a theme.

The page defines its three themes from 14-data-driven.json when it loads; the log underneath shows each call. Choose a page theme and a nested one, then reload: both come back. Add a theme from the form, or remove the current one.

defineTheme

themeSwitcher.defineTheme("ocean", {
  "--theme--light--color--primary": "#005f9e",
  "--theme--dark--color--primary": "#7cc4ff",
});

The second argument is a flat map of the input variables: the light and dark colours of the six palettes (chapter 3) and the tuning variables (chapter 10). The result is the same as a [theme="ocean"] { … } rule (chapter 6), and the switcher discovers it like any other, so it appears in onChange and can be set, nested and persisted the same way. Call it again with the same name to replace the theme.

The rule is written through the browser's stylesheet API, one <style data-theme="ocean"> in <head>, with each declaration set by setProperty. No CSS text is built from the data, so a value cannot escape its declaration.

What a row may hold

  • Colours. Any value the browser accepts as a colour. In the fixture, sunset has "tomato red" for its light error colour: it fails the check, is skipped with a warning in the console, and the rest of sunset is applied. defineTheme also returns the skipped keys, which is what the log prints.
  • Tuning. slate sets --theme--blend--darker-1 and --theme--density-scale (chapters 10 and 11). Tuning values are not checked; a bad one falls back to the default, as it would in CSS.
  • The six standard palettes only. A custom palette (chapter 8) needs the Sass that defines its tokens, so a key such as --theme--light--color--brand is skipped. Keys outside --theme-- are skipped too.

Restoring after a reload

The switcher stores the page theme's name (chapter 12), and on reload the head script and the switcher set it before the fixture has loaded. For a moment theme="sunset" has no rule, which chapter 6 showed is harmless: the page shows the defaults until defineTheme adds the rule, and CSS applies it then. So store the rows where the page can fetch them at start; a theme added from the form in the example is gone after a reload because nothing stores its row. The nested panel's theme is an attribute on that panel, outside the switcher, so the example remembers it itself with one localStorage line.

removeTheme

removeTheme("sunset") removes the <style> that defineTheme added. If it is the page theme, the attribute is cleared too; an element nested inside with that name keeps its attribute, so the example clears that one itself. Themes that come from a stylesheet are not affected.
