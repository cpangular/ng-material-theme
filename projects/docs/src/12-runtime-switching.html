Runtime switching

The first JavaScript. One small module finds the themes a page has, switches between them, switches light and dark, and remembers the choice.

The switcher

Everything so far was CSS: a theme is a rule, a mode is a declaration. To let a user change them, something has to set the theme attribute on <html> (chapter 6) and its color-scheme (chapter 2). That is all ThemeSwitcher does. It holds no colours and does no colour maths; core.css still derives every token. 

import { themeSwitcher } from "@cpangular/ng-material-theme/theme-switcher";

themeSwitcher is a ready-made instance. Importing it is enough: it discovers the page's themes, restores the stored choice and starts watching for new stylesheets. (It is also set on window, for a page without modules.)

Discovery

There is no list of themes to register. The switcher reads every stylesheet the page can access and collects the names in [theme="…"] selectors, so the three rules in the example's <style> are its three themes. A <style> or stylesheet <link> added later is picked up too. onChange(callback) calls you now and whenever the list or the page theme changes, with both; the example fills its select from that.

Switching the theme

setTheme("ember") sets theme="ember" on <html>; setTheme(null) removes it, which is the default theme of chapter 6. The name is not checked against the list: if its rule arrives later, CSS applies it then. The switcher manages the root element only; a nested theme is an attribute you set yourself.

Switching light and dark

setColorScheme("light") and ("dark") set an inline color-scheme on <html>, which chapter 2 showed forces a mode on the whole page. ("auto") removes it, so core.css's own color-scheme: light dark applies again and the page follows the operating system, with no listener needed: the browser re-resolves every light-dark() itself when the OS changes. onColorSchemeChange(callback) reports the mode, as "light", "dark" or "auto"; the example uses it to press the right button.

Persistence

Both choices are stored in localStorage, under @cpangular/ng-material-theme.selectedTheme and @cpangular/ng-material-theme.colorScheme, and put back when the switcher is created. Storage is per origin, so every page of a site shares the choice. On this site that includes the examples: pick a theme here and the site header follows on the next page load, and the other way round. A stored name a page has no rule for is still set, since a rule may arrive later (chapter 14); the example keeps such a name visible in its select instead of showing a blank. Pass { persist: false } to new ThemeSwitcher() for an instance that stores nothing.

Before first paint

The switcher is a module, so it runs after the page has started to render. For a moment the page would show the default theme and the OS mode, then jump. Three lines in <head>, before the stylesheets, read the same two keys and apply them first: 

<script>
  try {
    var t = localStorage.getItem("@cpangular/ng-material-theme.selectedTheme"), s = localStorage.getItem("@cpangular/ng-material-theme.colorScheme");
    if (t) document.documentElement.setAttribute("theme", t);
    if (s === "light" || s === "dark") document.documentElement.style.colorScheme = s;
  } catch (e) {}
</script>

The try is for browsers that block storage. The switcher then finds the attribute and the declaration already in place and changes nothing. Reload the example with a theme chosen: it does not flash.

This site

The header's select and its three buttons are this chapter's example again, as site code: the themes are rules in the site's stylesheet, the select is filled from onChange, the buttons call setColorScheme, and each page's <head> carries the script above. The site also copies its mode onto each example as it loads, because an example is its own document and the inline color-scheme on the site's root does not reach into it.

Source

The example loads ../theme-switcher.js, a copy the site keeps next to the examples, through an import map, so the import reads the package name as it would in your app. With a bundler, the import alone is enough.
