Using Sass

The same library as a Sass module: core() emits what core.css contains, and createTheme() writes the theme rules for you.

This is chapter 6 rebuilt in Sass. Here is chapter 6's CSS version again for comparison; the two render identically in both modes, apart from the single-colour mint.

Loading the module

The package exports its Sass entry point, so the idiomatic import is a pkg: URL: 

@use "pkg:@cpangular/ng-material-theme/theming" as theme;

The pkg: scheme needs the Node package importer: sass --pkg-importer=node on the command line, or importers: [new NodePackageImporter()] with the JavaScript API. Most bundler Sass loaders enable it. Without it, add --load-path=node_modules and write @use "@cpangular/ng-material-theme/theming" instead; both resolve to the same file.

core() replaces the link

@include theme.core(); emits exactly what core.css contains. Use one or the other, never both: a page that links core.css and also compiles core() registers every input twice and ships the derivation twice. The example page therefore has no core.css link, only its own compiled stylesheet.

createTheme()

createTheme($name, $config) is the Sass form of chapter 6's [theme="name"] { inputs } rule, and emits only what the config names, so nested themes inherit the same way. $is-default: true also applies the theme where no attribute is set, which is chapter 3's :root rule. The config is a map with a colors key, one entry per palette, in either of two shapes:

Shape Meaning
primary: #0f9f8f One colour, used in both modes.
primary: (#0b5fa5, #8ec5ff) A light value and a dark value.

Any of the six palettes may appear, and a palette left out is derived or inherited exactly as in chapter 6. createTheme() has no typography key: fonts are yours to set, and the library does not touch them.
