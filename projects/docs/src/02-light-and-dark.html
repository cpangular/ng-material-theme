Light and dark

Every token has a light value and a dark value. One CSS property decides which one you see, on any element.

Press Light, Dark and Auto at the top of this page. They set color-scheme on the example's root element, as your operating system would; Auto removes it, so core.css's default takes over again. The first two panels never change colour. The third sets nothing and follows the root.

The panels use Canvas and CanvasText, the browser's own page colours, for background and text; they follow the same switch. Chapter 5 replaces them with the library's own background and text tokens.

The default follows the OS

core.css sets color-scheme: light dark on the root element. That is the browser's own switch for light and dark mode: with both keywords, the page follows the operating system preference, with no script.

Forcing a mode on any element

color-scheme: light or color-scheme: dark on an element forces that mode for the element and everything inside it. Nothing else is needed: no attribute, no class, no second stylesheet. A dark panel inside a light page is one declaration.

Two values per token

The box is --color--primary in all three panels. core.css writes each token as light-dark(light value, dark value). A custom property passes that text down unchanged, so the browser picks one of the two only at the element that uses var(--color--primary), from that element's color-scheme, whether set on it or inherited from a parent. That is why forcing a mode works on any element.

In the light panel the box shows the light value. In the dark panel it shows the dark value, a lighter colour so that it stands out on a dark background. --color--primary--contrast changes with it, so the text stays readable. The next chapter sets those two values.
