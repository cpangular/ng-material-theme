Themes

A named theme is the inputs from chapter 3 behind an attribute. Put the attribute on any element and its subtree is re-themed.

The theme attribute

A theme is a plain CSS rule, [theme="ember"] { inputs }. Any element with theme="ember" gets those inputs, and every token inside it is re-derived from them: the palettes, the variants, the surfaces. Set it on <html> to theme the page, or on a panel to theme the panel. There is no list of themes to register; the rule is the theme.

The default theme

Chapter 3's :root rule was already a theme: the one that applies where no attribute does. Keep it, and add named themes next to it.

Nesting

Themes nest. A theme inside a theme inherits every input it does not set, because the inputs are ordinary inherited custom properties. Then it re-derives everything from what it has:

  • Inherited if not set: primary, error, and the tuning values of chapter 10.
  • Re-derived from primary unless set: secondary, tertiary, neutral, neutral-variant. In the example, accent sets only tertiary; its primary and secondary come from ember, and its surfaces are ember's surfaces.

Any value of the attribute works as a boundary, even one with no rule. An element with theme="x" and no [theme="x"] rule simply re-derives from what it inherits.

Themes and colour scheme

The attribute chooses the inputs; color-scheme from chapter 2 chooses which of the two values each token resolves to. They are independent, so they combine freely: the second panel forces light mode for a theme, and a card inside it goes dark with one declaration and no attribute. A theme is not a mode and a mode is not a theme.
