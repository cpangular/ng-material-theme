Themes

A named theme is the inputs from chapter 3 behind an attribute. Put the attribute on any element and its subtree is re-themed.

The theme attribute

A theme is a plain CSS rule, [theme="ember"] { inputs }. Any element with theme="ember" gets those inputs. core.css works out the tokens from the inputs on the root element, and again on every element with a theme attribute; any other element receives the finished tokens of its nearest such ancestor. So inside a themed element the palettes, the variants and the surfaces all follow its inputs, and inputs set on a plain <div> change nothing until it has a theme attribute. Set it on <html> to theme the page, or on a panel to theme the panel. There is no list of themes to declare anywhere; the rule is the theme.

The default theme

Chapter 3's :root rule was already a theme: the one that applies where no attribute does. Keep it, and add named themes next to it. In the example, only the page behind the two panels uses it.

If you put a theme attribute on <html>, write the named-theme rules after the :root rule: both match <html> with the same specificity, so the later one wins.

Nesting

Themes nest. The inputs are ordinary inherited custom properties, so a nested theme starts with its parent's inputs and then works out its own tokens from what it has:

  • Inherited unless the nested theme sets them: primary, error, and the tuning values (the variant percentages of chapter 4; chapter 10 shows how to set them).
  • Re-derived from primary unless the nested theme's own rule sets them: secondary, tertiary, neutral, neutral-variant. One of these set by the parent theme does not carry through; the nested theme works it out again from primary.

In the example, accent sets only tertiary. Its primary and error are inherited from ember, so its error chip is ember's magenta. Its secondary and its surfaces (built from neutral, chapter 5) are re-derived from that same primary, so they match ember's.

A theme attribute with no rule

An element with theme="x" and no [theme="x"] rule still works out its tokens again, from the inputs it inherits. That is what lets inputs set inline take effect: <div theme="x" style="--theme--light--color--primary: …">. Without the attribute the inline inputs would change nothing.

Themes and colour scheme

The attribute chooses the inputs; color-scheme from chapter 2 chooses which of the two values each token resolves to. That is why color-scheme needs no attribute: it changes no value, it only picks one of the two each token already holds. They are independent, so they combine freely: the second panel forces light mode for a theme, and a card inside it goes dark with one declaration and no attribute. A theme is not a mode and a mode is not a theme.
